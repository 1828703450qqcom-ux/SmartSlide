# SmartSlide 部署指南

本指南部署仓库根目录的轻量 Web 入口 `web_app.py`。它提供主题生成、任务查询、PPT 下载和前端页面，监听容器内 5000 端口。仓库同时包含更大的 `backend/app.py` 服务；这两套入口依赖和端口不同，以下命令不要混用。新增的 `Dockerfile.web` 与 `docker-compose.yml` 专门用于 `web_app.py`。

```text
浏览器 → 127.0.0.1:5000 → web_app.py → 已选文本模型 API
                                      └→ SVG/PPTX → output/
```

## 1. 配置模型与密钥

在仓库根目录复制模板：

```bash
cp .env.example .env
```

Windows PowerShell 使用 `Copy-Item .env.example .env`。打开 `.env`，将 `TEXT_MODEL_SOURCE` 设置为实际要用的厂商（例如 `deepseek` 或 `minimax`），将 `TEXT_MODEL` 设置为该厂商可用的模型名，并填入匹配的 `DEEPSEEK_API_KEY` 或 `MINIMAX_API_KEY`。只有选中的厂商需要密钥。`IMAGE_MODEL_SOURCE` 等配图配置按需填写；如果希望执行配图步骤，也要配置对应服务的密钥。不要把 `.env` 提交到 GitHub。

## 2. Docker Compose 启动（推荐）

需要 Docker Engine 和 Docker Compose v2。

```bash
git clone https://github.com/1828703450qqcom-ux/SmartSlide.git
cd SmartSlide
cp .env.example .env
# 编辑 .env 并填写真实模型密钥
docker compose config
docker compose up -d --build
docker compose ps
```

访问 `http://127.0.0.1:5000/`。Compose 默认仅监听宿主机回环地址；需要换端口时在 `.env` 添加 `APP_PORT=5001` 并重启。容器生成的文件保存在仓库的 `output/`，不会因为重建容器而自动删除。服务器对外提供服务时，请用 Nginx/Caddy 把 HTTPS 域名代理到本机 5000 端口，不要直接开放未加密端口。

## 3. Python 本地启动

建议 Python 3.11。安装依赖时使用仓库新增的 `requirements-web.txt`，避免 README 中旧的零散依赖命令遗漏 Pillow/CairoSVG。

```bash
python -m venv .venv
# Linux/macOS: . .venv/bin/activate
# Windows PowerShell: .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-web.txt
cp .env.example .env
# 编辑 .env 后启动
python web_app.py
```

访问 `http://127.0.0.1:5000/`。`python 生成PPT.py` 是独立命令行入口，同样使用根目录 `.env`；需要交互式命令行生成时可单独运行。Windows 的 `启动.bat` 指向仓库内嵌的 `python/python.exe` 和另一套 `backend/app.py`，普通 Git 克隆不包含内嵌 Python，故从 GitHub 克隆后应按上面的虚拟环境命令启动。

## 4. 验收与运维

```bash
curl http://127.0.0.1:5000/api/vendors
docker compose logs --tail=100 smartslide
```

`/api/vendors` 返回当前厂商和是否发现对应密钥。再在网页提交一个短主题，观察任务状态和下载是否成功；这一步会实际调用模型服务，可能产生 API 费用。更新前备份 `.env` 与 `output/`，然后 `git pull && docker compose up -d --build`。回滚时恢复上一个 Git 提交、重建容器并保留对应输出文件。

## 5. 限制与排障

| 现象 | 检查项 |
|---|---|
| `/api/vendors` 的 `has_key` 为 `false` | `TEXT_MODEL_SOURCE` 与密钥变量前缀必须匹配；修改 `.env` 后重建容器。 |
| 模型请求失败 | 核对厂商 API Key、模型名、账号额度和网络连通性。 |
| 下载按钮报“文件不可用” | 查看任务是否完成以及 `output/` 的写入权限。 |
| 原 README 的 `docker-compose up -d` 无法运行 | 使用本仓库新增的 `docker compose up -d --build`；旧版仓库没有 Compose 文件。 |

轻量入口的任务状态保存在进程内存中，服务重启后历史任务状态不会恢复；PPTX 文件仍保留在持久化的 `output/`。该模式适合个人或小团队使用。面向多用户生产环境时还需要任务队列、持久化状态、鉴权和配额控制。仓库中的旧 `backend/Dockerfile` 依赖未随仓库提供的 `pyproject.toml`，因此不属于本指南的可执行路径。
